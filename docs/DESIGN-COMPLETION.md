## 仍未关闭的验收

1. **真人试玩。** 五位无说明的新玩家需记录首次过关率 40–60%、前 90 秒安全率 ≥80%、自发现鲸歌 ≥70%、Boss 平均 2–3 次、心结复述率 ≥60%，并至少一人 15 分钟内通过第一关并解释 Grok 的行为。另需三人验证 HUD、移动路径、预警可读性与色盲/高对比体验，听验高密度音效、背景切换、20 鱼 连吃、道具在 0.5 秒内辨识、看见至少三种生态事件。
2. **实机硬件。** AMD Ryzen 5 7530U 的 Radeon 核显启用了 Chrome Canvas2D 硬件加速，1080p 的 60 秒负载测试达到帧率和首屏预算。Windows 进程采样已记录。浏览器任务管理器中的整局峰值要求 ≤220MB，目前不能签收。GPU 进程为浏览器公用，慢帧的 GC 归因也尚无记录。
3. **严格美术。** 64px 黑色剪影供人工盲识。全体描边宽度与严格两级阴影、动作逐帧反馈、实机原版/新版主观比较还要人工审片。背景抽样不覆盖鱼、角色与穿插道具。个别资产的导出尺寸或代码画法与 03 表中的分件建议有差异。
4. **严格代码规范。** 命名导出、模块分层、源文件长度、渲染只读有检查。色板已归入 `palette.js`，并添加了数据结构注释。扫描仍发现 3,305 个裸数字，热路径仍有对象建造点，部分共享结构与提示未达到原文条款。
5. **体验数值与时间。** 当前普通控制器的熟练路线，模拟计时约 75–136 秒。它证明门槛和回路真实可走。真人 12–15 分钟、五场 Boss 目标时长、捷径节时及经济循环仍需采样。没有强行加等待。
6. **数值冲突。** 采用 02 的 360 秒浅梦保底覆盖 05 节拍总长 450 秒。三体型下皇鱼为 2 阶并受护甲限制，鮟鱇只能反杀。旋律按 D1 末、D2 门后、D3 门前放置。升级使用逐级表，总价 1370，文档概述 830 与之相冲突。07 最后 Perfect 与 08 唤醒调同时成立才合唱。

## 可重复验证

- [本轮机器验证摘要](audit/verification-2.2.json)记录五关路线、浏览器状态、像素差、音效和实机帧率。[真人试玩记录表](audit/PLAYTEST.md)保留未签收条款和空白结果。新增资产和生成提示词见 [提示词档案](audit/ASSET-PROMPTS.json)。
- `npm test` 运行纯逻辑及元系统测试。 `npm run test:smoke` 验证常规键鼠、界面、危险状态、加载和存档。
- `node tools/full-run.mjs` 从新档从头只用移动、扑咬和按住/松开唱歌。写出普通输入、状态与字幕事件摘要。 `node tools/browser-replay.cjs` 用浏览器真实菜单和相同输入，核对五份状态哈希。加 `--record` 生成整个活动的视频。探索加速，潜梦和 Boss 按原时钟播放。
- `node tools/visual-check.cjs` 比较回放截图的固定十个画面，容差 2%。首次基线仅供同平台回归，真人审美仍另验。
- `npm run test:perf`、`npm run test:audio`、`node tools/audio-freq.cjs`、`node tools/architecture-check.cjs` 和 `node docs/audit/runtime-text-count.mjs` 分别检查浏览器、音频、架构和活动文字。局部配置差异需要在报告里保留。
