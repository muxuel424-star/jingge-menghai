# 《鲸歌梦海》设计文档集 v2

> 本目录是**唯一权威设计源**。代码与文档冲突时，以文档为准；文档内部冲突时，按下面「权威顺序」裁决。
> 写给执行方（Codex / 人类程序）看，不是宣传物料。

## 怎么读

| 顺序 | 文档 | 回答什么问题 |
|---|---|---|
| 1 | `01-设计总纲.md` | 这游戏到底是什么、不做什么、成功的判据 |
| 2 | `02-核心循环与数值.md` | 一局怎么走、资源怎么流、每个数是多少 |
| 3 | `05-世界与关卡.md` | 五关分别长什么样、每段要玩家学到什么 |
| 4 | `06-生态与敌人.md` | 每种生物怎么读、怎么反、怎么吃 |
| 5 | `07-Boss设计.md` | 五场 Boss 的完整分镜与招式表 |
| 6 | `03-美术圣经.md` / `04-音频圣经.md` | 画成什么样、听成什么样 |
| 7 | `08-道具旋律与成长.md` | 道具、鲸歌、局外成长、经济 |
| 8 | `09-技术架构.md` | 代码怎么分层、数据怎么组织、怎么测 |
| 9 | `10-开发计划与验收.md` | 分几个里程碑、每张任务卡怎么算做完 |

## 权威顺序

1. `02` 的**数值表**（具体数字）
2. `01` 的**支柱与反支柱**（原则）
3. `07` / `05` / `06` 的**表格**（内容）
4. `03` / `04` 的**规范条款**（表现）
5. `09` / `10` 的**结构与方法**（实现）

出现「文档没写」的情况：**不要自由发挥**。按 `01` 的支柱推导，然后在 PR 描述里写明「文档缺项 + 我的推断」，等设计方确认。自由发挥是这版文档要根治的头号问题。

## 给执行方的三条硬规矩

1. **不许新增未在文档中出现的玩法系统。** 想加，先在任务卡外单独提，等确认。
2. **每个里程碑结束必须能打包运行并截图。** 不许出现「重构完了但跑不起来」的中间态提交。
3. **改数值只改 `src/data/tuning.js`。** 任何 `.js` 里出现魔法数字都算缺陷。
